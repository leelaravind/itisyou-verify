Four Explicit Verification Statuses

Common Integration Failure Modes

3 Ways Downstream Systems Drop Records Silently

Workflows can return HTTP 200 upon handoff even when downstream asynchronous jobs fail or drop payload fields.

mark_email_read
Failure Mode 01

Asynchronous Queue Drop

A webhook receiver returns HTTP 200 immediately to confirm ingress, then pushes the body to an internal queue. If the asynchronous background worker crashes or exhausts memory, the downstream record never materialises.

AUDIT IMPACT: Missing downstream records go undetected until manual reconciliation.
rule
Failure Mode 02

Schema Drift & Attribute Stripping

A destination API modifies an internal field definition or deprecates a currency key. The receiving endpoint quietly strips unrecognized payload segments and stores an incomplete object without returning an error.

AUDIT IMPACT: Incomplete records pass initial status checks with missing required fields.
speed
Failure Mode 03

Rate Limit Disconnect

During high-volume batch executions, subsequent steps hit API rate limits or connection pool exhaustion, causing secondary records to be dropped while earlier steps report success.

AUDIT IMPACT: Partial multi-step transactions remain uncommitted in secondary tools.

The 3-Step Verification Protocol

Independent Multi-System Verification

Post-execution readback checks query downstream APIs separately to confirm actual record creation.

01STEP 1: INGRESS

Decoupled Inspection Queue

Register an expected outcome webhook via HTTP POST. Registers the intended destination record keys without altering production workflows.

// Webhook receiver check request
POST https://verify.itisyou.com/v1/assert
expect: { target: "hubspot.deal", id: "{{deal_id}}" }
02STEP 2: AUDIT

Direct Destination Inspection

After a configurable settling period (e.g. 5s), ITISYOU queries target APIs directly to inspect state: valid record ID, updated fields, and matching foreign keys.

// Direct Target REST Query
GET https://api.hubapi.com/crm/v3/objects/deals/{{deal_id}}
settling_window: 5000ms // timeout: 5000ms
03STEP 3: RESOLUTION

Audit Record & Alerting

When verified, an audit record is logged with destination object IDs and timestamps. When evidence is missing or inconclusive, it dispatches an immediate notification webhook.

// Verification Status: LOGGED
match: confirmed (hubspot_id: 84920)
audit_log: payload_matched
