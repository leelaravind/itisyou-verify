Architectural Rationale // Strict Indeterminacy Isolation

"The rule evaluation grammar is restricted to a finite, deterministic set of typed operators so that FAILED (asserted false by destination query) and UNVERIFIED (could-not-be-checked due to timeout, rate-limiting, or unreachable target) remain strictly distinguishable. A general expression language (or Turing-complete scripting) was explicitly rejected because ambiguous nulls, evaluation exceptions, and unhandled expressions collapse the distinction between a true failure and a system observation failure."
